## 2. Project Vision

SVARTÁLFAR is a personal project created to collect and organize everything I learn and experience throughout my journey of studying and working.

It is more than a conventional programming blog or portfolio.

It is a personal knowledge archive where I can:

- Document what I learn.
- Record practical experiences from work.
- Organize technical and non-technical knowledge.
- Save useful notes, ideas, and discoveries.
- Document projects, experiments, and implementations.
- Share knowledge with other people.
- Look back at my progress and development over time.

The core idea:

**A place to document the journey, preserve knowledge, and turn experiences into understanding.**

## 3. Project Goals

The project should achieve these goals:

1. Build a centralized place for personal knowledge.
2. Create a structured system for organizing learning materials.
3. Document both theoretical knowledge and practical experience.
4. Connect related topics to create a broader understanding.
5. Maintain a long-term learning history.
6. Make knowledge accessible and shareable through a public website.

The project should grow naturally over time as I learn new things and gain more professional experience.

## 5. Content Philosophy

Knowledge should not simply be collected. It should be understood, organized, connected, and continuously improved.

Each article or knowledge block should prioritize:

- Clear explanations.
- Practical examples.
- Real-world applications.
- Step-by-step learning.
- Problems and solutions.
- Connections to related concepts.
- References and useful resources.

Avoid unnecessarily academic explanations or complicated terminology when simpler explanations are possible.

However, technical documentation must remain sufficiently detailed and accurate.

## 8. Technical Direction

The project is intended to be a lightweight, maintainable static website.

Suggested technology stack:

- Astro: Static site framework.
- TypeScript: Type safety.
- Tailwind CSS: Styling.
- Markdown / MDX: Knowledge documentation.
- Astro Content Collections: Content organization and validation.
- Pagefind: Search functionality.
- Mermaid: Technical diagrams.
- GitHub Actions: Automated deployment.
- GitHub Pages: Website hosting.

Prefer static generation and simple architecture. Avoid adding unnecessary backend services or infrastructure unless the project genuinely requires them.
